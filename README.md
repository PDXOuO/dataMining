# 高校图书馆个性化图书推荐 — 初赛提交包

图书馆推荐算法竞赛（C 题）参赛作品。本仓库同时是**可运行模型包**：跑一条命令即可从原始数据生成提交文件。

## 一、交付物

| 交付物 | 路径 | 说明 |
|---|---|---|
| 验证集结果 | `outputs/result.csv` | 956 行，覆盖全部读者 ID，每行 10 条索书号 |
| 承诺书 | `outputs/承诺书.pdf`（可编辑版 `.docx`） | 待填写队伍名称与签字 |
| 技术报告 | `outputs/技术报告.pdf` | 13 页，中英文摘要 + 相关工作 + 四折消融 + 十条被否定路径 + 参考文献 |
| 模型包 | 本仓库 | 含源码、依赖清单、一键脚本、Dockerfile |

## 二、快速开始

```bash
pip install -r requirements.txt
python run.py
```

`run.py` 会调用预测脚本生成 `outputs/result.csv`，并自动执行四项格式校验：读者 ID 全覆盖、行内无重复、每行 ≤ 10 条、无空行。

其他入口：

```bash
python run.py --check             # 仅校验已有结果文件
python scripts/report_tables.py   # 四折 × 7 变体对照表，写入 docs/results.md
python scripts/backtest.py --split 2024-09-01
```

Docker 方式：

```bash
docker build -t librec .
docker run --rm -v "$PWD/outputs:/app/outputs" librec
```

## 三、模型概述

赛题的核心约束是**验证集读者 ID（`R0001`）与训练集读者条码无法关联**，因此用户级协同过滤、序列模型、元学习冷启动在物理上不可实现。方案重心落在群体统计信号与物品侧信号：

1. **院校 × 中图法二级类目的分层贝叶斯热度**：以「学院对某类目的偏好占比 × 该类目内全局份额」作为先验，与学院原始物品计数按 λ=1.5 收缩，得到该学院对每本书的偏好分；
2. **历史同类目提权**：老人组对其历史覆盖过的二级类目乘以 (1+1.6)，保留同类目内的热度排序，不替换为长尾；
3. **新书分位数先验**：新书无借阅记录，按其所在二级类目内有记录图书的第 70 百分位赋分，每份列表最多保留 2 本新书（实测新书占借阅的 7.3%，故不作主力）。

全流程无训练、无随机性，单核 CPU 约 60 秒完成。

## 五、赛题与提交约束

| 项目 | 要求 |
|---|---|
| 训练数据 | 29841 条 / 5107 读者 / 13525 索书号（2022-01-01 ~ 2025-01-16） |
| 验证输入 | 956 行，读者 ID 为匿名 `R0001` 形式 |
| 候选新书池 | 7386 册（去重后，GBK 编码） |
| 提交粒度 | **索书号**（不是条形码） |
| 提交格式 | 每行 `读者ID,推荐索书号列表`，竖线分隔，最多 10 个，必须覆盖全部 956 个 ID |
| 分组 | 新人 674 人（610 人无任何历史）、老人 282 人（要求推荐未借过的新书） |
| 总分 | `(0.4 × 新人组 + 0.6 × 老人组) × 100` |
| 新人组 | `0.5 × HitRate@10 + 0.5 × Recall@10` |
| 老人组 | `0.4 × HitRate@10 + 0.3 × Recall@10 + 0.3 × NDCG@10` |

## 六、分支策略

一个分支 = 一套完整可运行的方案。分支从 `main` 切出，通过对比文档汇报，不直接合并多个方案到 `main`。

| 分支 | 定位 |
|---|---|
| `main` | 汇总：公共底座、文档规范、最终选定方案 |
| `solution/a-popularity` | 全局 / 分群热门基线（参照系） |
| `solution/b-group-migration` | 专业画像分群迁移（专攻新人组） |
| `solution/c-itemcf-hybrid` | 物品共现 + 内容 + 新书池三路召回 |
| `solution/d-two-stage-ranker` | 多路召回 + GBDT 精排 |
| `solution/e-dept-bayes` | **院校-类目分层贝叶斯（最终选用）** |

方案对比与取舍理由见 [`docs/branches.md`](docs/branches.md)，规则解读与文献调研见 [`docs/research.md`](docs/research.md)。
