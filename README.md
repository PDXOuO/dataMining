# 高校图书馆个性化图书推荐 — 算法竞赛方案库

本仓库用于管理「图书推荐算法竞赛（C 题）」的多套候选方案。每条技术路线在独立分支上开发与验证，`main` 只保留汇总信息与最终选定方案，便于横向对比后择优。

## 一、赛题与提交约束（以组委会《验证集说明》为准）

| 项目 | 要求 |
|---|---|
| 训练数据 | `data/2022-2025处理后借阅信息.xlsx`，29857 条 / 5112 读者 / 13525 索书号（2022-01-01 ~ 2025-01-16） |
| 验证输入 | `data/验证集发放.csv`，956 行，读者 ID 为匿名 `R0001` 形式 |
| 候选新书池 | `data/中文入藏（新书）.csv`，8297 条（GBK 编码） |
| 提交粒度 | **索书号**（不是条形码） |
| 提交格式 | 每行 `读者ID,推荐索书号列表`，竖线分隔，最多 10 个，必须覆盖全部 956 个 ID |
| 分组 | 新人 674 人（610 人无任何历史）、老人 282 人（要求推荐未借过的新书） |
| 总分 | `(0.4 × 新人组 + 0.6 × 老人组) × 100` |
| 新人组 | `0.5 × HitRate@10 + 0.5 × Recall@10` |
| 老人组 | `0.4 × HitRate@10 + 0.3 × Recall@10 + 0.3 × NDCG@10` |

> 完整规则解读、文献依据与取舍理由见 [`docs/research.md`](docs/research.md)。
> 各分支方案对比见 [`docs/branches.md`](docs/branches.md)。

## 二、分支管理策略

一个分支 = 一套完整可运行的方案。分支从 `main` 切出，开发完成后通过 PR 或对比文档汇报，**不直接向 `main` 合并多个方案**，避免相互污染。

| 分支 | 定位 | 状态 |
|---|---|---|
| `main` | 汇总分支：公共文档、目录规范、最终选定方案 | 维护中 |
| `solution/a-popularity` | 方案 A：全局 / 分群热门基线（保底参照） | 设计完成 |
| `solution/b-group-migration` | 方案 B：专业画像分群迁移（专攻新人组） | 设计完成 |
| `solution/c-itemcf-hybrid` | 方案 C：物品共现 + 内容 + 新书池三路召回（主力） | 设计完成 |
| `solution/d-two-stage-ranker` | 方案 D：多路召回 + GBDT 精排（冲分增强） | 设计完成 |

分支命名规范：`solution/<序号>-<方案简称>`；公共基础设施类改动使用 `feat/`、`fix/`、`docs/` 前缀。

## 三、提交信息规范

采用 Conventional Commits，格式 `<type>(<scope>): <中文描述>`。

- `feat`: 新增功能或方案实现
- `fix`: 修复缺陷
- `docs`: 文档
- `refactor`: 重构（不改变行为）
- `exp`: 实验性改动（含参数与结论）
- `chore`: 构建、依赖、配置

示例：
```
feat(pipeline): 增加横表 Excel 解析与索书号标准化
exp(c-itemcf): 时间衰减系数 0.85 -> 0.70，验证集 HitRate +0.8pp
docs(research): 补充冷启动分群迁移的文献依据
```

每次实验性提交必须在正文中写明**指标变化**，否则视为无效提交。

## 四、目录结构

```
.
├── data/                      # 赛题数据（原始文件入库，中间产物忽略）
├── docs/
│   ├── research.md            # 规则解读、文献调研、方案取舍论证
│   ├── branches.md            # 各分支方案对比表
│   └── solutions/             # 各方案设计文档（分散在对应分支）
├── src/                       # 公共代码（数据加载、评测、提交校验）
├── scripts/                   # 一键运行脚本
├── outputs/                   # 运行产物（忽略）
└── README.md
```

## 五、环境与复现

```bash
# Python 3.12
uv sync                       # 或 pip install -r requirements.txt
python scripts/validate_submission.py outputs/result.csv   # 提交前校验
```

复现要求（对应评分细则中的资格线）：
1. 固定随机种子，所有随机过程可复现；
2. 单条命令从原始数据生成最终 `result.csv`；
3. 软硬件环境、依赖版本写入 `docs/research.md` 附录。
