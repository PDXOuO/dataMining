# 方案 C：物品共现 + 内容相似 + 分群热门 三路召回融合

> 分支：`solution/c-itemcf-hybrid`
> 定位：**主力方案**，同时覆盖老人组（60% 权重）与新人组（40% 权重）

## 1. 目标

在**不使用任何需要用户 ID 对齐的模型**的前提下，把总分从热门基线的 4.3 分拉到 12 分以上。核心是老人组——它占 60% 权重，且只有具备个体历史建模能力的方案才能吃到。

## 2. 为什么是这个结构

评分结构决定了两类读者必须用两套逻辑：

| | 新人（674） | 老人（282） |
|---|---|---|
| 可用信号 | 只有画像 | 完整的借阅历史列表 |
| 组内公式 | `0.5 Hit + 0.5 Recall` | `0.4 Hit + 0.3 Recall + 0.3 NDCG` |
| 有 NDCG 吗 | 无 | 有 |
| 列表策略 | 10 次独立押注，最大化**覆盖** | 前段**精排**，后段覆盖 |

因此：新人走分群通路（方案 B），老人走共现 + 内容通路，融合层按类型切换。

## 3. 三路召回

### 3.1 通路一：物品共现（老人主力）

**构图**：用训练集 5112 人 + 验证集 956 人的历史列表，合并成「读者 → 索书号」交互集合。两条来源的差异在于训练集有精确时间戳、验证集只有有序列表，构图时统一按位置近似时间。

**相似度**：对二分交互矩阵计算余弦相似度，再做双重抑制：

```
sim'(i, j) = sim(i, j) · f_time(i, j) / (pop_i^α · pop_j^α)
```

- `f_time`：共现对的时间衰减，`exp(−Δdays / τ)`，`τ` 初值 365 天；
- 分母为热门惩罚（RP3β 思路），`α` 初值 0.5。图书馆场景下「人人都借」的教材类会污染共现，这一步不可省。

**打分**：对读者历史 `H`（有序，最近的排后），

```
score(item) = Σ_{h ∈ H} sim'(h, item) · recency(h)
recency(h) = 0.5 ^ (距今天数 / 180)
```

保留 Top-50 作为候选，**必须排除该读者历史中出现过的全部索书号**（评分规则：已借过的书不计分）。

**退化处理**：老人中位历史仅 4 册，281 人中有相当比例历史 < 3。对历史 ≤ 2 条的读者，共现权重自动降至 0.2，改由分群通路主导。

### 3.2 通路二：内容相似（新书与长尾的入口）

新书池 8297 册没有任何借阅记录，共现通路无法覆盖，只能靠内容。

三种相似度加权拼接：

| 特征 | 计算方式 | 权重 |
|---|---|---|
| 中图法类目 | 一级类目精确匹配 + 二级类目前缀匹配 | 0.5 |
| 责任者 | 责任者字段规范化（去「著/编/主编」）后精确匹配 | 0.3 |
| 题名 | 字符 2-gram TF-IDF 余弦 | 0.2 |

作用：把新书映射到「最相似的老书」上，从而借用老书的共现关系进入候选池。

### 3.3 通路三：分群热门（新人主力 + 老人兜底）

完整复用方案 B：专业 → 学院 → 全局三级回退 + 贝叶斯平滑 + 类目配额。

## 4. 融合

采用加权 RRF，而非学习型融合——956 名读者没有任何标注答案，无法训练融合权重；RRF 只依赖排名，对三路分数量纲差异免疫。

```
final(item) = Σ_r w_r / (k + rank_r(item)),  k = 60
```

权重按用户类型切换（初值）：

| 用户类型 | 共现 | 内容 | 分群 |
|---|---|---|---|
| 老人（历史 ≥ 3） | 0.60 | 0.25 | 0.15 |
| 老人（历史 < 3） | 0.20 | 0.25 | 0.55 |
| 新人（无历史） | — | 0.25 | 0.75 |

## 5. 列表构造

融合后得到候选排序，再按类型重排：

**老人**：前 4 位取融合分最高的项（服务 NDCG），后 6 位在剩余候选中按类目分散选取（服务 Recall）。分散规则：同一中图法一级类目最多出现 2 次。

**新人**：直接按方案 B 的配额（专业超额类目 6 + 文学保底 3 + 新书 1），不做融合精排。

## 8. 回测方案（本方案的前置条件）

**没有回测就不许调参。** 构造方式：

1. 取单一全局切分点 `T`（主用 2024-09-01，交叉验证用 2024-03-01）；
2. 训练侧只用 `T` 之前的借阅记录；候选池只保留 `T` 之前已入藏的索书号；
3. 答案侧取 `T` 至 `T + 14 个月` 的借阅记录，模拟验证集的 14 个月窗口；
4. 答案侧读者按「`T` 之前是否有历史」划分新人/老人，与验证集的 674/282 比例对齐；
5. 老人答案剔除其在训练期已借过的书（与评分规则一致）；
6. 指标按验证集的加权公式计算。

**严禁**在 `T` 之后的数据上计算热度、共现或新书权重——Ji et al.（TOIS 2023）已证明时间泄漏会使 nDCG 虚高 21.7%~73.4%，且模型排名会反转。

## 9. 实现要点与坑

1. **不要用 RecBole 训练**：RecBole 需要标准 `user_id:token` 格式的交互文件，而验证集读者无法映射为训练集用户。强行构造会得到 956 个孤立用户，模型退化为统计。
2. **共现矩阵维度**：13525 个索书号 + 8297 册新书，稀疏矩阵用 `scipy.sparse`，稠密矩阵约 1.8GB，不可行。
3. **索书号是推荐粒度，不是册**：同一索书号多复本合并计数，否则共现被复本数放大。
4. **验证集历史列表的语义**：它是「按时间排序、按索书号去重」的，最后一个元素是最近借的，不能打乱顺序后当作无序集合使用（recency 权重依赖顺序）。
5. **老人 1 例历史为空**：需走新人逻辑，代码里不能假设老人必有历史。
6. **融合后去重**：同一索书号可能从三路同时召回，RRF 天然合并，但输出前仍要校验重复。
