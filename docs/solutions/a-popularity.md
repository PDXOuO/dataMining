# 方案 A：全局 / 分群热门基线

> 分支：`solution/a-popularity`
> 定位：参照系与兜底方案，非竞争性方案

## 1. 目标

用最小代价跑通「原始数据 → 956 行 result.csv」的完整链路，同时为后续所有方案提供可比的数值锚点。本方案不追求名次，追求**正确性**与**可对照性**。

具体要验证的四件事：

1. Excel 横表解析、GBK 编码的新书 CSV 读取是否正确；
2. 提交格式（读者 ID 覆盖、竖线分隔、≤10 条、索书号合法性）是否合规；
3. 官方公布的同学院热门基线能否在本仓库复现；
4. 分群粒度从「学院」细化到「专业」时，指标是否真的提升。

## 2. 核心思路

不做个性化排序，直接按热度输出。但热量口径按群体切分，形成三档：

| 档位 | 统计范围 | 用途 |
|---|---|---|
| 全局热门 | 全馆借阅频次 Top-N | 兜底，保证任何读者都有 10 条输出 |
| 学院热门 | 同一学院读者的借阅频次 Top-N | 对应官方基线，用于复现校准 |
| 专业热门 | 同一专业读者的借阅频次 Top-N | 验证「专业粒度优于学院粒度」的假设 |

每档内部再按「近 12 个月热度」与「全期热度」两种口径各算一遍，共 6 个变体，用于消融。

## 3. 关键实现

### 3.1 热度口径

- **计数单位是索书号，不是册**。同一索书号可能有多个复本（20847 册 / 15433 种题名 / 13525 个借阅出现的索书号），必须先去重再计数，否则复本多的书会被系统性放大。
- **时间衰减**：`weight = 0.5 ^ (Δ天数 / half_life)`，`half_life` 取 180 天与 365 天两档做对比。
- **热门惩罚（可选）**：对全局 Top-50 的书乘以 `0.8`，避免列表被少数教材占满，为长尾留出位置。该项在初赛评分中可能为负收益（无多样性加分），仅作消融对照。

### 3.2 分群字段归一化

训练集的学院字段有同义写法，例如「经管学院」与「经济与管理学院」、「数计学院」与「数学与计算机学院」，必须先做映射表归并，否则分群统计会被拆散。

验证集的「学院」已是规范化后的值，以验证集取值为主表，训练集向它映射。

### 3.3 候选池与过滤

- 候选 = 训练集出现过的索书号 ∪ 新书池索书号；
- 老人（282 人）需过滤掉其历史借阅索书号列表中的全部条目（评分规则：推荐已借过的书不计分）；
- 新人（674 人）无需过滤。

### 3.4 输出

每行 `读者ID,索书号1|索书号2|...`，UTF-8 编码，956 行，覆盖全部 ID。

## 4. 预期指标

| 变体 | 新人 HitRate@10 | 老人 HitRate@10 | 预估总分 |
|---|---|---|---|
| 全局热门 | 0.040 | 0.057 | 3.3 |
| 学院热门 | 0.073 | 0.057 | 4.3 |
| 专业热门（若可用） | 0.08 ~ 0.10 | — | 4.5 ~ 5.5 |

前两行直接取自组委会公布的基线，本方案的首要任务是**把这些数字复现出来**。若复现不出，说明数据解析或口径有问题，必须先修正再继续其他方案。

## 5. 实现要点与坑

1. **训练 Excel 是横表结构**：表头在第 3 行（`header=None` 读入后索引为 2），数据从索引 3 开始，第 0 列是「序号」。直接 `read_excel` 会得到错位的 DataFrame。
2. **新书 CSV 是 GBK 编码**，用 UTF-8 读取会抛 `UnicodeDecodeError`。
3. **验证集 CSV 是 UTF-8-BOM**，需 `encoding='utf-8-sig'`，否则首列名会带 `\ufeff`。
4. **索书号可能存在首尾空格与全半角差异**，需要 strip + 统一。
5. 老人中 1 人历史列表为空，需按新人逻辑处理，不能假设老人必有历史。

## 6. 与主线的衔接

本分支的产出物有两个：

- 一个可运行的热门基线脚本，作为方案 C 中「分群热门」通路的直接复用件；
- 一组校准过的基线数字，写入技术报告的「实验设置」章节，用于证明评测流程可信。

方案 B 在本方案基础上把分群粒度做细，方案 C 在本方案基础上叠加个性化召回。
